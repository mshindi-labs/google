# `@mshindi-labs/google` v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `@mshindi-labs/google` v1 (`/core`, `/gmail`, `/postgres`, `/testing`), a multi-tenant Gmail-send library with per-tenant OAuth clients and envelope-encrypted credentials.

**Architecture:** `/core` owns crypto, the OAuth flow, the token cache, events, and errors. It talks to persistence through `CredentialStore`, to key material through `KeyProvider`, and to Google's OAuth endpoints through `OAuthGateway`, so each can be faked in tests. `/gmail` builds on `/core` through a symbol-keyed internals handle. `/postgres` implements `CredentialStore` over a driver-agnostic `query` function.

**Tech Stack:** TypeScript 5.9, Node ≥ 18, tsup, vitest, `google-auth-library`, `@googleapis/gmail`, `nodemailer` (MailComposer), `html-to-text`, `@electric-sql/pglite` (tests), semantic-release.

**Spec:** `docs/SPEC.md` (read it alongside this plan; § references point there).

## Global Constraints

- Package name `@mshindi-labs/google`. Subpath exports `./core`, `./gmail`, `./postgres`, `./testing`. No root export.
- `"engines": { "node": ">=18.0.0" }`. ESM + CJS via tsup, `.d.ts` emitted. MIT license.
- Tooling copied from `../gsheets`: `.releaserc.json`, `commitlint.config.cjs`, `.husky/`, `.gitignore`, `lint-staged` config, prettier. Commit messages follow Conventional Commits.
- `google-auth-library` is the only runtime `dependency`. `@googleapis/gmail`, `nodemailer`, `html-to-text`, `mailparser`, `@google-cloud/kms`, `@aws-sdk/client-kms` are **optional peer dependencies**, loaded with `loadPeer()` (Task 1). A missing peer throws `MissingPeerDependencyError` naming the `npm i` command.
- Invariants I1–I7 (spec §2) apply to every task.
- Scopes: `BASE_SCOPES = ['openid', 'email']`. Gmail: `https://www.googleapis.com/auth/gmail.send`.
- OAuth state TTL is 10 minutes. State is 32 random bytes as base64url, stored as a SHA-256 hash. PKCE uses S256.
- AAD format: `mshindi-google/v1|tenant=<tenantId>|record=<record>:<recordId>|field=<field>`.
- Gmail limits: attachments total ≤ 25 MiB (`MAX_ATTACHMENT_BYTES = 26_214_400`). The raw message uses the media upload path above 5 MiB (`UPLOAD_THRESHOLD_BYTES = 5_242_880`).
- Send retries: max 3 attempts, full-jitter exponential backoff, base 250 ms, cap 8 s; `Retry-After` honored when present.
- Spec §16 open items get these defaults: one `hostedDomain` per tenant; expired-state cleanup is host-scheduled via `google.oauth.purgeExpiredStates()`; no audit retention helper; MIT.
- **Deviation from spec §13:** Postgres tests use PGlite (real Postgres compiled to WASM, in-process) instead of Testcontainers, so CI needs no Docker. `FakeGoogleOAuth` fakes the `OAuthGateway` interface instead of HTTP endpoints.

## Review Focus

1. **Google reports `email` as `https://www.googleapis.com/auth/userinfo.email`** in the granted-scope string. The scope check must compare service scopes only, so a successful consent isn't rejected as missing scopes. Test in Task 8.
2. **Email case mismatch.** An admin types `Careers@SunCulture.io` and the ID token says `careers@sunculture.io`; the connection should succeed. Normalize both sides with `trim().toLowerCase()`. Test in Task 7 and Task 8.
3. **Non-ASCII names and subjects** (e.g. `Wanjirũ`, `Ofa ya kazi ✅`). They must pass validation and be RFC 2047-encoded, not rejected as "control characters". Test in Task 10 and Task 11.
4. **Double-submitted callback** (the browser refreshes the callback URL). The second call gets `InvalidOAuthStateError`, and exactly one connection row exists. Tests in Task 8 (in-memory) and Task 13 (Postgres contract).
5. **Client ID changed while access tokens are cached.** The next send for that tenant must fail with `ConnectionRevokedError` immediately, not keep sending for up to an hour on a cached token. Test in Task 9.

  - `interface GmailTransport { send(p: { accessToken: string; raw: Buffer; threadId: string | null }): Promise<{ messageId: string; threadId: string }> }`

At or below the threshold it sends `requestBody: { raw: base64url, threadId }`; above it, `media: { mimeType: 'message/rfc822', body: raw }`.
  - `type SendErrorClass = { kind: 'retry'; delayMs: number | null } | { kind: 'unauthorized' } | { kind: 'fail'; error: GoogleLibError }`
  - `classifySendError(err: unknown): SendErrorClass`
  - `withSendRetry<T>(fn: () => Promise<T>, opts?: { maxAttempts?: number; baseMs?: number; capMs?: number; sleep?: (ms: number) => Promise<void>; random?: () => number }): Promise<T>`
  - `createGmail(google: GoogleCore, opts?: { blockedAttachmentExtensions?: string[]; transport?: GmailTransport }): { send(input: SendInput): Promise<{ messageId: string; threadId: string }> }`
  - `/testing`: `class CaptureTransport implements GmailTransport { readonly messages: CapturedMessage[]; clear(): void; find(pred: (m: CapturedMessage) => boolean): CapturedMessage | undefined }`, where `CapturedMessage = { raw: Buffer; threadId: string | null; parsed: { from: string; to: string[]; cc: string[]; bcc: string[]; subject: string; html: string | null; text: string | null; attachments: { filename: string; contentType: string; size: number }[] } }`. Parsing uses `mailparser` via `loadPeer`. Message IDs are `capture-<n>`.

Classification table (spec §8.3):

| Input | Result |
|-------|--------|
| `code` in `ENOTFOUND, EAI_AGAIN, ECONNREFUSED`, or starting `ERR_TLS_` / `CERT_` | `retry` |
| status 429, or 403 with `reason` in `rateLimitExceeded, userRateLimitExceeded` | `retry`, with `delayMs` from `Retry-After` (seconds or HTTP date) |
| 403 with `dailyLimitExceeded`, or a message matching `/sending limit/i` | `fail` `DailyQuotaExceededError` |
| 401 | `unauthorized` |
| 400 | `fail` `InvalidMessageError('message')` |
| `ECONNRESET, ETIMEDOUT, ESOCKETTIMEDOUT`, `socket hang up`, `AbortError`, any 5xx | `fail` `SendOutcomeUnknownError` |
| other | `fail` `GoogleApiError(status, reason)` |

When retries run out on a rate-limit, throw `RateLimitedError(lastDelayMs)`; after pre-send network errors, throw `GoogleApiError(0, code)`. Backoff: `delay = delayMs ?? random() * min(capMs, baseMs * 2 ** attempt)`.

`send` pipeline (spec §8.2):
1. `validateSendInput`.
2. `tokens.getAccessToken` (enforces tenant and active status).
3. `assertServiceScopes(connection.scopes, ['gmail'])`.
4. `buildMime` with `from = { name: input.fromName ?? connection.displayName, address: connection.email }`.
5. `withSendRetry(transport.send)`. On `unauthorized`: run once more with `forceRefresh: true` and, if it's still 401, `updateConnectionStatus(…, 'revoked', 'unauthorized')`, emit `connection.revoked`, and throw `ConnectionRevokedError('unauthorized')`.
6. `touchConnection`.
7. Emit `message.sent` (`to/cc/bcc` addresses, `subject`, `attachmentCount`). On any error, emit `message.failed` with `errorCode` and rethrow.

  - `rewrapAll(opts: { store: CredentialStore; keyProvider: KeyProvider; fromKeyId?: string; batchSize?: number }): Promise<{ rewrapped: number; skipped: number; failed: { record: string; error: string }[] }>`
  - `verifyAll(opts: { store: CredentialStore; keyProvider: KeyProvider; batchSize?: number }): Promise<{ ok: number; failed: { record: string; error: string }[] }>`

Behavior:
- `record` strings look like `connection:<id>.refresh_token`.
- Values whose `kid` already equals `currentKeyId`, or doesn't equal `fromKeyId` when given, are skipped. That makes reruns idempotent and lets them resume.
- A failure on one value is recorded and the run continues.
- `error` is the error `code` only, never detail.
- Default `batchSize` is 100.
