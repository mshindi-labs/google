# Calendar Service Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `@mshindi-labs/google/calendar`: availability, slot suggestions, and
create/reschedule/cancel/status of guest events on a tenant mailbox's calendar, with no
duplicate invites.

**Architecture:** A new `src/calendar/` service mirrors `src/gmail/`: input validation, a
`CalendarTransport` seam over `@googleapis/calendar`, an error classifier with bounded
retries, and `createCalendar(google)` built on the existing core internals (token manager,
store, emitter). Slot maths is a pure, exported function using `Intl` only.

**Tech Stack:** TypeScript, Node ≥ 18, vitest, tsup (ESM + CJS), `google-auth-library`,
optional peer `@googleapis/calendar`.

**Spec:** `docs/superpowers/specs/2026-11-05-calendar-design.md` (design) on top of
`docs/SPEC.md` (v1 core). Read both. Section refs below like "D§5.3" point at the design.

## Review Focus

1. A timeout on an insert that actually landed → retry gets 409 → must resolve to the
   same event with no second invite and exactly one `calendar_event.created`.
2. DST days (America/New_York 2026-03-08 and 2026-11-01): suggested slots never at a
   non-existent wall time, never duplicated in the repeated hour.
3. Attendee given with different case than organizer / duplicates (`Ann@X.com`,
   `ann@x.com`, the organizer's own address) → one guest, organizer dropped.
4. A raw gaxios error with an `Authorization` header reaching any public method → the
   thrown error and every emitted event contain no token.
5. `updateEvent` with a full attendee list: kept guests keep their RSVP; on a retried
   patch whose first attempt landed, no false failure.

Each line has a pinning test in the owning task (marked **[RF n]**).

### Task 2: Time-zone helpers and `findCommonSlots`

**Files:**

- Create: `src/calendar/types.ts` (Shared vocabulary above), `src/calendar/time.ts`, `src/calendar/slots.ts`
- Test: `test/calendar/time.test.ts`, `test/calendar/slots.test.ts`

**Interfaces — Produces:**

- `assertTimeZone(tz: unknown, field: string): string` — throws `InvalidEventError(field)` unless `new Intl.DateTimeFormat("en-US", { timeZone: tz })` succeeds.
- `zonedParts(at: Date, tz: string): { year; month; day; hour; minute; weekday: Weekday }` (month 1–12).
- `zonedToInstant(p: { year; month; day; hour; minute }, tz: string): Date | null` — `null` when the wall time doesn't exist (DST gap); for an ambiguous wall time returns the **earlier** instant. Algorithm (the tests don't fully determine it):
  ```
  guess = Date.UTC(y, m-1, d, h, min)
  offsetAt(t) = wallAsUTC(zonedParts(t)) - t
  for offset of [offsetAt(guess), offsetAt(guess - offsetAt(guess)), ±1h neighbours]:
      cand = guess - offset
      collect cand if zonedParts(cand, tz) equals p
  none collected → null; else return min(collected)
  ```
- `findCommonSlots(input: { now: Date; window: TimeRange; durationMinutes: number; workingHours: WorkingHours; workingHoursByAttendee?: Record<string, WorkingHours>; busy: Record<string, TimeRange[]>; bufferMinutes?: number; stepMinutes?: number; minNoticeMinutes?: number; maxResults?: number }): TimeRange[]`
  Defaults 0 / 15 / 60 / 10. Validates: duration int 5..480, step int 5..60, buffer int 0..240,
  minNotice int 0..10080, maxResults int 1..50, window end > start and ≤ 31 days, HH:MM
  `start < end`, every tz via `assertTimeZone` → else `InvalidEventError("<fieldName>")`.
  Attendees = keys of `busy`, matched case-insensitively against `workingHoursByAttendee`.
  Candidates: for each calendar day (in `workingHours.timeZone`) touching the window, wall
  times from 00:00 in `stepMinutes` steps, each converted once with `zonedToInstant`
  (gaps skipped, repeated hour used once). Keep a candidate when: `start ≥ window.start`,
  `end ≤ window.end`, `start ≥ now + minNotice`; for every attendee the whole `[start,end)`
  lies inside one working interval of that attendee's own hours on that attendee's local
  day; and it doesn't overlap any busy block widened by `buffer` on both sides. Sorted
  ascending, cut at `maxResults`.

- `retry.ts`:
  `classifyCalendarError(err): { kind: "retry"; delayMs: number | null } | { kind: "unauthorized" } | { kind: "duplicate" } | { kind: "gone" } | { kind: "fail"; error: GoogleLibError }` —
  `GoogleLibError` → fail as-is; 429 / 403 with rate reasons → retry (Retry-After); 401 → unauthorized; 409 → duplicate; 404/410 → gone; 400 whose messages match `/conference/i` → fail `ConferencingUnavailableError`; other 400 → fail `GoogleApiError(400, reason)`; ≥ 500 → retry; network codes (`ENOTFOUND, EAI_AGAIN, ECONNREFUSED, ECONNRESET, ETIMEDOUT, ESOCKETTIMEDOUT`, TLS, `AbortError`, "socket hang up") → retry; other status → fail `GoogleApiError(status, reason)`; anything else → fail `GoogleApiError(0, code)`. ### Task 7: Calendar service — `createEvent`

**Files:** Modify `src/calendar/service.ts`; Test `test/calendar/service-create.test.ts`

**Interfaces — Produces:** `createEvent(input: CreateEventInput): Promise<CalendarEventView & { created: boolean }>`.

Behaviour (D§5.3, D§5.3.1):

- `id = deriveEventId(tenantId, connection.email, key)`; body: summary, description, start/end `{ dateTime: ISO, timeZone }`, attendees (no `responseStatus`), `location` for in-person, `guestsCanInviteOthers: false`, `guestsCanModify: false`, `guestsCanSeeOtherGuests`, private stamp incl. `mshindiFingerprint`.
- **in_person:** insert with caller `sendUpdates` (mapped `external_only → externalOnly`), `mshindiInvite: "sent"`, `conferenceDataVersion: 0`.
- **google_meet:** (1) insert `sendUpdates: "none"`, `mshindiInvite: "pending"`, `conferenceData.createRequest = { requestId: randomUUID(), conferenceSolutionKey: { type: "hangoutsMeet" } }`, `conferenceDataVersion: 1`; (2) conference status `success` → continue; `pending` → `get` with sleeps `[500, 1000, 2000, 3000, 3500]`; `failure` or still pending → `delete` (`sendUpdates: "none"`) and throw `ConferencingUnavailableError` (message says to retry with a new idempotency key); (3) patch `{ extendedProperties: { private: { mshindiInvite: "sent" } } }` with caller `sendUpdates`. Step 3 is **verify-then-retry**: on a retryable failure, `get` and treat `mshindiInvite === "sent"` as done; otherwise retry (bounded by the same attempt count).
- Insert wrapped in `withCalendarRetry`. `DuplicateEventSignal` → `get(id)`: unmanaged / other tenant / `mshindiKey` differs → `EventConflictError`; cancelled → `EventConflictError`; fingerprint differs → `EventConflictError` (message: use `updateEvent`); `mshindiInvite === "pending"` → resume at (2); else success.
- `created` flag: `true` if **this call** issued an insert attempt that could have landed (a 409 seen only after an earlier attempt in the same call failed with a retryable error); `false` if the very first insert attempt got 409 (a replay of an earlier call).
- Emit `calendar_event.created` exactly once, only when `created: true` and invites are sent. Any thrown error → `calendar_event.failed` (`operation: "create"`) then rethrow.
